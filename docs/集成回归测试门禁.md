# sider2api 推送门禁 · 集成回归测试框架

> 目标：**每次 `git push` 到远端（触发生产部署）之前，自动用当前工作区代码跑完整集成回归，100% 通过才放行。**

## 一、门禁如何工作

`git push` 会触发仓库的 `pre-push` hook（位于 [.githooks/pre-push](../.githooks/pre-push)），它按顺序执行：

| 步骤 | 内容 | 失败即拦截 |
|---|---|---|
| 1 | `deno check deno_pro.ts`（静态类型检查） | ✅ |
| 2 | 用【当前工作区代码】起本地临时实例（独立端口 `8010`，与日常开发端口 8000 隔离） | ✅ |
| 3 | `pytest -m "not perf"` 完整集成回归（覆盖全部能力端点，消耗真实 sider 额度） | ✅ |
| 4 | 清理临时实例 | — |

只有全部通过，推送才继续执行。任何一步失败，推送被中止并提示修复。

## 二、安装（一次性）

```bash
cd /d/Github_repo/sider2api
git config core.hooksPath .githooks
```

安装后每次 `git push` 自动触发门禁。

## 三、使用

```bash
# 正常推送（默认跑完整回归 ~3 分钟）
git push

# 快速自检（零额度冒烟 ~15 秒，适合临时验证）
SIDER2API_SMOKE=1 git push

# 手动跑门禁（不推送）
PYTHONIOENCODING=utf-8 /d/anaconda3/envs/python310/python.exe scripts/run_regression.py
PYTHONIOENCODING=utf-8 /d/anaconda3/envs/python310/python.exe scripts/run_regression.py --smoke

# 调试：测试后保留临时实例
PYTHONIOENCODING=utf-8 /d/anaconda3/envs/python310/python.exe scripts/run_regression.py --keep-server
```

### 逃生门（慎重）

```bash
git push --no-verify   # 绕过 pre-push hook
```

> ⚠️ `--no-verify` 是 git 原生机制，用于紧急/已人工确认的场景。
> 门禁存在是因为"推送即上线生产"（见 [开发测试发布SOP.md](开发测试发布SOP.md)），
> 绕过意味着**未经回归验证的代码可能直接部署**。仅在明确知道后果时使用。

## 四、测试覆盖（完整回归内容）

`pytest -m "not perf"` 覆盖（标记分层见 [pytest.ini](../pytest.ini)）：

- **smoke**：主页 / 模型清单契约 / CORS / 404 / 鉴权 / stats 页面与快照契约
- **chat**：6 个代表模型非流式 + 流式 + system + content 数组
- **multiturn**：X-Session-ID 多轮记忆
- **think**：-think 后缀推理（非流式 + 流式）
- **image**：专用图像端点 + 对话触发图像
- **gemini / anthropic / openai**：三大协议格式（含流式契约）
- **tools**：Function Calling 降级
- **vision**：视觉输入 → not_supported
- **errors**：缺参 400 / 鉴权 401 / 未知模型回退

## 五、环境要求

| 依赖 | 说明 |
|---|---|
| deno | PATH 或 `~/.deno/bin/deno` |
| python310 | anaconda3 环境，含 requests/pytest |
| `.env` | `SIDER_AUTH_TOKEN`（上游额度）+ `AUTH_TOKEN`（服务端认证） |

- hook 自动查找 python310：优先 `PYTHON310` 环境变量，再探测常见路径，最后回退 `python`。
- 临时实例用**当前工作区**的 `deno_pro.ts`——即使有未提交改动，也测的是即将推送的内容。
- 完整回归**消耗真实 sider 额度**（约 40+ 次上游调用），属预期成本。

## 六、新增测试文件的自动纳入

只要新测试文件命名 `test_*.py` 放在 [test/](../test/)、使用现有 `client` fixture 和 marker，
门禁的 `pytest -m "not perf"` 会自动纳入。无需改门禁脚本。

## 七、常见问题

| 现象 | 处置 |
|---|---|
| 门禁失败但想先看错误详情 | 直接跑 `scripts/run_regression.py`，输出含 pytest 完整结果 |
| 临时实例端口冲突 | `scripts/run_regression.py --port 8011`（hook 默认 8010） |
| 实例起不来 | 看 `regression_server.log`（仓库根，测试后保留） |
| 想完全关掉门禁 | `git config core.hooksPath` 置空（不推荐） |
