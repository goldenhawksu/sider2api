# sider2api 项目记忆

## 2026-10-07：模型信息文本转 Excel、核实模型并更新 MODEL_MAPPING

### 前置步骤：JSON/类 JSON 模型信息转 Excel

以下前置过程由用户补充，发生在本次对话的上游模型验证之前：

1. 用户提供 JSON/类 JSON 格式的模型信息文本或文档。
2. 用下方提示词，通过代码解析和整理原始模型信息，形成 `sider_models_no_icon.xlsx`。
3. 将生成的 Excel 作为后续验证输入，读取 `name` 列逐一核实 Sider 上游，再按验证结果更新 `MODEL_MAPPING`。

本轮保存用户提供的生成要求与流程来源；前置阶段的原始文本、解析日志及下载链接未在当前对话中提供，因此这里不补写其原文条目数、解析异常或实际输出列。后续验证阶段已通过代码确认收到的 Excel 有 135 条数据。

模型信息文本转 Excel 的提示词原文（全文保留）：

```text
请将我上传的文档（JSON/类JSON格式的模型配置列表）整理为表格，要求如下：

【数据处理】

1. 用代码解析原文件，不要靠阅读或推测来整理内容。
2. 提取全部条目，一条都不能遗漏、不能合并、不能自行补充。
3. 删除所有 icon 字段（包括其中的 SVG 等内容）。
4. 保留除 icon 以外的全部字段，字段名与原文一致。
5. 嵌套字段展开为独立列，用"父字段.子字段"命名（如 cost.type、cost.count、cost.multiplier）。
6. 原文中某条目缺少的字段留空，不要填默认值或推测值。
7. 文本内容（如 desc）保持原文，不改写、不润色、不翻译。
8. 保持原文顺序，并加一列"索引"标注原始序号（从0开始）。

【输出】 9. 生成 .xlsx 文件并提供下载链接；首行为表头。 10. 同时在回复中说明：

- 原文共解析出多少条，表格共多少行（两者必须一致）
- 共有哪些列
- 是否有解析失败或格式异常的条目（如有，逐条列出）

【禁止】

- 不得编造原文中不存在的条目、字段或描述。
- 如果无法完整解析文件，直接告诉我原因，不要给出部分或推测的结果。
```

### 任务与结果

用户要求读取仓库根目录 `sider_models_no_icon.xlsx` 的 `name` 列，逐一核实 Sider 上游可用性；禁止并发，每分钟不超过 6 次，失败调用可以忽略；根据结果更新 `deno_pro.ts` 的 `MODEL_MAPPING` 并出报告。

本次正式验证于北京时间 2026-10-07 09:21—09:47 完成，共 135 个唯一模型名，105 个通过、30 个未通过。映射由 62 项更新为 105 项，新增 51 项、移除 8 项。实测最短请求起点间隔为 11 秒，任意 60 秒内最多 6 次，前后请求响应无重叠。代码修改仅涉及 `MODEL_MAPPING`，未提交、未推送。

完整逐项结果及新增列表见 [模型可用性核实报告](模型可用性核实报告_20261007.md)。这些结果是当时凭证及聊天接口下的实测快照，后续更新需要重新验证。

### 执行过程

1. 检查工作区状态和项目约定，读取 `CLAUDE.md`、`docs/sider上游调用开发规则.md`，定位 `deno_pro.ts` 的映射、请求模板、插件请求头和 Think 判定逻辑；避免改动用户已有的未跟踪文件。
2. 用 `openpyxl.load_workbook(..., read_only=True, data_only=True)` 读取 `models` 工作表，以第一行为列名，提取 `name`，核对行数与唯一名称数量；本表包含 135 项，也包含停用、历史、图像及 Slides/Research 专用标识。
3. 请求模型使用 `name` 原值；不按 `enable` 过滤，不使用 `displayName`，不把 `replaceBy` 作为请求目标。表格的停用标记不能直接代替接口实测结果。
4. 复用 `test/upstream_client.py` 的 `load_token()`、`UpstreamClient.build_body()` 和插件请求头，从环境变量或 `.env` 读取 `SIDER_AUTH_TOKEN`，通过 `requests` 直连 `https://sider.ai/api/chat/v1/completions`，不输出认证值。
5. 固定提示词为 `请只回复 OK，不要解释，不要调用工具。`，使用 `stream=true`、空会话 `cid`、`tools={"auto": []}`；模型名包含 `-think` 时启用 `think_mode.enable`，与现有代码保持一致。
6. 使用单个串行循环；下一次请求必须等上一次响应读取结束或连接关闭后才能发出，并确保两次请求起点相隔至少 11 秒。失败不自动重试，逐项将脱敏结果写入 JSON，支持按已验证的模型名继续执行。
7. 读取完整响应，解析 SSE 中的顶层 `code`、`msg` 及 `data.type`，累计文本、记录事件类型与模型回显；响应使用上下文管理器关闭连接。记录请求起止时间、HTTP 状态、业务码、耗时和传输异常类型，不保存含潜在敏感地址的完整网络异常字符串。
8. 成功条件为 HTTP 200、无业务错误、无传输异常、响应读取完成、文本非空；本次所有最终成功项还均回显请求模型名。只有 HTTP 200、会话事件或额度事件不能算成功。
9. 完成全部 135 项后，按时间记录审计任意 60 秒窗口内请求次数、最短间隔和请求重叠情况，再生成映射；保留现有模型分组及原条目相对顺序，各组追加验证成功的新名称。
10. 运行静态检查、现有本地模拟回归、模型发现接口校验及新增名称转发校验；这些验证仅访问本地模拟上游，不再消耗真实 Sider 额度。最后确认映射外代码和输入表格未变，生成中文报告及脱敏证据。

### 关键发现与限制

- 30 个未通过项：模型或参数校验错误 19 项（code 1000）、连接失败 7 项、平台繁忙 2 项（code 10002）、账号方案限制 1 项（code 707）、模型回显不一致 1 项。
- `chat-deep-research` 返回有效文本但回显 `sider`，最终标记为目标模型未确认，未纳入映射；需要检查回显以识别这种路由差异。
- `gpt-5.4` 普通版返回繁忙，`gpt-5.4-think` 成功；基础版和推理变体需要独立验证。
- `claude-fable-5-think` 的 code 707 明确提示升级账号方案；不能仅凭业务码套用历史文档中的固定含义，应结合本次消息判断。
- 表格中多个 `enable=false` 的旧模型仍可调用并回显自身名称，最终按实测收录。
- 连接、繁忙、权限失败不能证明模型永久下线；这些项本次跳过，没有为取得成功而反复重试。
- 图像、Slides 和 Research 标识只测试当前映射使用的聊天接口，其专用接口可用性未核实。
- Sider 的模型回显只确认其接受和回显该标识，不能独立确认背后的供应商或权重版本。
