## 三、上下文窗口

**能力边界**（由 deno_pro.ts 的上游保护 + 实测推导）：

| 维度 | 上限 | 依据 |
|---|---|---|
| 字符数 | ~49,500 字 | deno_pro `SIDER_MAX_CHARS`，上游 text 字段上限 |
| 词数 | ~6,000 词 | deno_pro `SIDER_MAX_WORDS`，实测超词触发 code:603 |
| 超限行为 | 返回 `context_length_exceeded` | 上游 code:603 → deno 翻译为标准错误 |

**各模型家族差异**：所有 59 个模型共用同一上下文拼接策略（deno 在请求前做字符/词数截断），因此 **59 模型上下文窗口一致**，均由 deno 层保护。历史上限为上游 code:603（约 8,810~22,000 字起触发），deno 保守截断到 49,500 字 / 6,000 词以避免触发。

> 注：本次未做逐模型递增长度实测（成本高），上下文边界以 deno 层统一保护 + 上游实测为准。

## 五、图像识别能力

**上游不支持视觉输入**（能力门控，铁律不 fake）：

```
OpenAI chat 图像输入 → HTTP 422
{"error":{"message":"上游 sider 不支持视觉输入 (图像理解)。请仅发送文本内容。...","type":"not_supported","code":"vision_not_supported"}}
```

- **59 个模型全部无图像识别能力**——deno 层在入站统一拦截视觉输入，返回标准 `not_supported`，绝不静默丢给上游
- 覆盖 OpenAI（image_url）/ Gemini（inline_data）/ Anthropic（image source）/ Responses（input_image）四种协议格式

## 八、结论与建议

1. **模型可用性一流**：59 模型全可用，无静默降级，生产稳定。
2. **图像生成注意选型**：优先用 GPT/Gemini/DeepSeek/开源系（可靠）；claude-opus 系列可能限流、claude-fable 被禁、grok-4.6 偶发失败。
3. **无图像识别是硬边界**：上游 sider 不支持，deno 已按能力门控原则优雅降级（不 fake）。
4. **上下文上限受 deno 保护**：49,500 字 / 6,000 词，超限返回标准 `context_length_exceeded`。
